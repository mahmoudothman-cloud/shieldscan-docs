## 3. Architectural Decisions

Cross-references Q1-Q7 brainstorming chain locks (§1) + Phase 0 v2 empirical findings (§2.2).

### 3.1 Q1 (γ) Section-Dispatch Architecture

**Decision:** New iOS adaptors + platform-gated invocation in current `parseReport`. Preserves single-parser-entry pattern at `internal/tools/docker/service/mobsf/parser.go` line 195-209. Existing 8 Android adaptors gated to `platform=="android"`; new 5 iOS adaptors gated to `platform=="ios"`.

**Implementation surface:** `parseReport` receives `platform string` parameter (V-CC current shape); existing 8-adaptor unconditional block becomes 8-adaptor `platform=="android"` block + new 5-adaptor `platform=="ios"` block. Bounded ~30-40 LoC parser.go refactor.

**Rejected alternatives:** Option (α) per-platform `parseReport` split (fragments entry points); Option (β) extended struct without resolution (doesn't solve `binary_analysis` collision); Option (δ) `appsec` aggregated (architecture-asymmetry; loses per-section granularity).

### 3.2 Q2 (a) iOS Adaptor Enumeration (Mandatory-Only v1)

**5 mandatory adaptors (empirical-data-grounded):**

1. **`adaptInfoPlist`** — parses raw plist XML (`info_plist` field; ~4856 chars empirical); extracts known-risky keys (`NSAppTransportSecurity` + `CFBundleURLTypes` + `NSAllowsArbitraryLoads` + etc.); emits findings per security-relevant key. NEW adaptor pattern (XML-parse not structured-JSON).
2. **`adaptATSFindings`** — parses `ats_analysis` `{ats_findings + ats_summary}`; mirrors existing `adaptNetworkSecurity` shape; reuses `mapMobSFSeverity`. Bounded structured-JSON adaptor.
3. **`adaptDylibAnalysis`** — parses `dylib_analysis` list × 8 sub-checks per .dylib; mirrors `adaptBinaryAnalysis` pattern; reuses `binarySubChecks` constant. ~50 LoC adaptor.
4. **`adaptIOSBinary`** — parses `binary_analysis` iOS dict `{findings + summary}`; resolves `binary_analysis` shape collision via Q3 mechanism (`json.RawMessage` + platform-conditional unmarshalling). Severity from finding-level field.
5. **`adaptBundleURLTypes`** — parses `bundle_url_types` list; emits findings per `CFBundleURLScheme` (URL scheme hijacking detection per OWASP MASVS-PLATFORM-3). NEW adaptor pattern (URL scheme enumeration).

**Forward-pinned (out of scope; empty in DVIA-v2 empirical):** `adaptMachoAnalysis` + `adaptFrameworkAnalysis` + `adaptIOSAPI`. Forward-pin trigger: ***"Begin MobSF V10 iOS empty-section adaptor expansion task"*** when populated-state testbed surfaces those sections.

### 3.3 Q3 (a) `binary_analysis` Shape Collision Resolution

**Mechanism:** `json.RawMessage` + platform-conditional re-unmarshalling.

Go struct field: `BinaryAnalysis json.RawMessage `+ "`" + `json:"binary_analysis"` + "`"

`parseReport` platform switch:

- Android: `var binaries []AndroidBinaryEntry; json.Unmarshal(r.BinaryAnalysis, &binaries); adaptBinaryAnalysis(binaries, platform)`
- iOS: `var iosBinary IOSBinarySummary; json.Unmarshal(r.BinaryAnalysis, &iosBinary); adaptIOSBinary(iosBinary, platform)`

Bounded ~5-10 LoC parser.go addition. Canonical Go polymorphic-JSON pattern.

### 3.4 Q4 (a) Per-Section Adaptor Pattern Instance Count

**Lock:** V10 is 1st-instance expansion (NOT 3rd instance). MobSF stays at 1 instance of per-section-adaptor pattern with Android+iOS section heterogeneity. SQLMap stays at 2nd instance (2 adaptors). Pattern count remains at 2 instances; 3rd-instance threshold per Task 7.6 P5.D + `1c6041d` canonical scope NOT triggered.

**Rationale:** Per-section adaptor pattern is "consumer with heterogeneous section data"; MobSF is one consumer with internal heterogeneity expansion. 3rd-instance would be a 3rd structurally-distinct consumer. Internal expansion ≠ new instance.

## 4. iOS Adaptor Enumeration + Section Schemas

### 4.1 `adaptInfoPlist` (info_plist; raw XML)

**Section shape:** Raw plist XML string (~4856 chars empirical in DVIA-v2).

**Adaptor pattern:** plist-parse via Go stdlib OR third-party `github.com/howett/plist` (verify at Stage 3 execution); extract known-risky keys per OWASP MASVS-PLATFORM checks.

**Emit-targets:** RawFinding per security-relevant key (`NSAllowsArbitraryLoads` true → high severity; `CFBundleURLSchemes` registered → bundled with `adaptBundleURLTypes`; `NSAppTransportSecurity` exceptions → medium severity per granularity).

**Estimated LoC:** ~80-120 LoC (largest new adaptor due to XML parsing + key-enumeration).

### 4.2 `adaptATSFindings` (ats_analysis)

**Section shape:** `{ats_findings: [{issue, severity, description}], ats_summary: {high, warning, info, secure}}` (DVIA-v2 empirical).

**Adaptor pattern:** Mirror `adaptNetworkSecurity` (Android `network_security` equivalent); iterate `ats_findings`; map severity via `mapMobSFSeverity` (unchanged from Android lowercase canonical).

**Emit-targets:** RawFinding per `ats_findings` entry; `FindingType="ats_violation"`; Severity from `mapMobSFSeverity`; Description from issue + description fields.

**Estimated LoC:** ~40-60 LoC.

### 4.3 `adaptDylibAnalysis` (dylib_analysis)

**Section shape:** List × 8 sub-checks per .dylib entry (DVIA-v2 had 20 .dylib entries; same 8-sub-check pattern as Android `binary_analysis`).

**Adaptor pattern:** Mirror `adaptBinaryAnalysis`; reuse `binarySubChecks` constant + per-sub-check severity rubric.

**Emit-targets:** RawFinding per sub-check per .dylib; `FindingType="dylib_protection_missing"`; Severity per sub-check; `Metadata.dylib_name` + `Metadata.sub_check` populated.

**Estimated LoC:** ~50-70 LoC.

### 4.4 `adaptIOSBinary` (binary_analysis iOS dict shape; Q3 collision-resolved)

**Section shape:** `{findings: {<title>: {detailed_desc, severity, cvss, cwe, owasp-mobile, masvs}}, summary: {high, warning, info, secure, suppressed}}` (DVIA-v2 empirical).

**Adaptor pattern:** Iterate findings dict; emit RawFinding per title-key with `detailed_desc` + `cvss` + `cwe` + `owasp-mobile` + `masvs` typed-field reuse (per Q6 ADR-024 + ADR-027 Metadata conventions).

**Emit-targets:** RawFinding per finding title; `FindingType="ios_binary_finding"`; Severity from finding-level field; CVSS + CWE + OWASP-MASVS populated.

**Estimated LoC:** ~60-80 LoC.

### 4.5 `adaptBundleURLTypes` (bundle_url_types)

**Section shape:** List of `{CFBundleURLName + CFBundleURLSchemes: [...]}` (DVIA-v2 had 1 entry with 2 schemes: `"dvia"` + `"dviaswift"`).

**Adaptor pattern:** Iterate `bundle_url_types` list; emit RawFinding per `CFBundleURLScheme` (URL scheme hijack risk per OWASP MASVS-PLATFORM-3).

**Emit-targets:** RawFinding per scheme; `FindingType="ios_url_scheme"`; Severity per scheme-risk-rubric (custom schemes without verification = high; well-known schemes = info); `Metadata.url_scheme` populated.

**Estimated LoC:** ~30-50 LoC.
