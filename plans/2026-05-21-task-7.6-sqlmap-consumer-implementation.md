## 3. Architectural Decisions (Plan-Level Locks)

Brainstorming chain Q1–Q9 architectural decisions locked at design doc `d8e25b5`. Plan-level refinements + Y-decisions captured below.

### 3.1 Q1 (a) Stdout Parsing — Framework Implementation Shape

**Lock:** Consumer `ParseOutput` receives DockerRunner stdout bytes; parses `--disable-coloring` text via log-prefix filter; per-section adaptor dispatch (Q2 lock). NO framework Mounts capability used (Q1 (a) confirms Task 7.5e Mounts NOT required for SQLMap).

**Implementation surface:** `parser.go` top-level `parseSQLMapOutput([]byte) ([]events.RawFinding, error)`; helper `stripLogPrefixes` scrubs `[INFO]`/`[WARNING]`/`[ERROR]`/`[CRITICAL]` lines; section-dispatch identifies injection block vs DBMS-fingerprint block boundaries.

### 3.2 Q2 (a) Per-Section Adaptor Pattern — 2nd Instance

**Lock:** Two adaptor functions in `parser.go`:

- `adaptInjectionFindings(text string) []events.RawFinding` — per-Parameter block parser; flattens N technique entries to N findings per parameter
- `adaptDBMSFingerprint(text string) (events.RawFinding, bool)` — trailing single-object parser; returns finding + presence-bool (DBMS section only present when ≥1 injection found)

**2nd-instance per-section-adaptor pattern empirically grounded:** MobSF (1st instance; 7 adaptors at `sections.go`) + SQLMap (2nd instance; 2 adaptors). `1c6041d` forward-pin operationally satisfied; pattern stays at 2 instances pending 3rd-instance evaluation per scope-mismatch methodology from Task 7.1 P5.D `aa3fb5f`.

### 3.3 Q3 (a) Per-Technique Finding Granularity

**Lock:** Per-parameter block flattens to N findings (one per technique). Each finding carries discrete `Title` + `Type` + `Payload`. Per-parameter aggregation rejected (loses `Payload` typed-field; loses per-technique severity differentiation; loses industry-standard granularity matching Burp Suite + ZAP).

### 3.4 Q4 (a) DBMS-Fingerprint Emission Semantics

**Lock:** DBMS-fingerprint emitted as discrete finding when present (DBMS section only emitted by SQLMap when ≥1 injection found). `FindingType="dbms_fingerprint"`; `Severity="info"` (lowercase canonical per ZAP/MobSF/Trivy precedent); single emission per scan. No-injection scans emit zero findings.

### 3.5 Q5 (a) ScanConfig.Depth → SQLMap `--level`/`--risk` Mapping

**Lock:** Three-tier mapping:

| ScanConfig.Depth | --level | --risk | Expected duration |
|---|---|---|---|
| quick (default) | 1 | 1 | ~10–15s |
| standard | 3 | 2 | ~30–60s |
| deep | 5 | 3 | ~3–5min |

Implementation: `buildArgs` conditional on `cfg.Depth` value; default `"quick"` if unset.

### 3.6 Q6 Metadata-vs-Typed Routing

**Typed-field reuse (per ADR-024 + Q6 typed-promotion principle):**

- `Title` (per-technique injection title; "DBMS detected: <type> <version>" for DBMS finding)
- `Severity` (`"critical"` or `"high"` for injection — technique-driven; `"info"` for DBMS)
- `FindingType` (`"sql_injection"` / `"dbms_fingerprint"`)
- `CWEID` (`"CWE-89"` for sql_injection findings; empty for DBMS)
- `TargetURL` (scan URL)
- `Parameter` (injection parameter name; sql_injection findings only)
- `Payload` (injection payload string; sql_injection findings only)
- `OWASP` (`"A03:2021 Injection"` for sql_injection findings)

**Metadata keys (snake_case per ADR-027; omit-when-empty):**

- `technique` — per-technique Type (boolean-based blind / error-based / time-based blind / UNION query / stacked queries)
- `place` — parameter place (GET / POST / COOKIE / HEADER)
- `dbms_type` — DBMS type (DBMS finding only; e.g., `"MySQL"`)
- `dbms_version` — DBMS version (DBMS finding only; e.g., `">= 5.1"`)
- `dbms_os` — server OS (DBMS finding only; e.g., `"Linux Debian 9"`)
- `web_app_tech` — web application technology (DBMS finding only; e.g., `"Apache 2.4.25"`)

**Forward-pin (v1.1+ candidates):** `request` + `response` typed-field promotion if log-file parsing adopted later; per-payload `http_request_count` if useful for downstream analytics.
