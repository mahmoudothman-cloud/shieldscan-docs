## 4. Verification Methodology

Per Task 7.5c V4 §4 precedent: 6-step per-surface cycle for each S1-S7 surface:

1. **Baseline** — capture pre-state (surface should be empty or known initial state)
2. **Populate** — create state (testbed APK upload + scan for S1-S3; synthetic state injection via discovered API for S4-S7)
3. **Verify-present** — confirm populated state via inspect method (docker exec + sqlite/filesystem for S1-S3; REST API for S4-S7)
4. **Cleanup-call** — invoke POST `/api/v1/delete_scan` with hash parameter
5. **Verify-reset** — re-inspect via same method as step 3; capture post-state
6. **Record verdict** — RESET_COMPLETE / PARTIAL_RESET / NOT_RESET / FAILED_TO_VERIFY per §7 framework

**Inspection method per surface category** (per Q3-(α) refinement): S1-S3 source-code-known surfaces use container-internal access (docker exec + sqlite3 against MobSF `db.sqlite3` + filesystem `ls`); S4-S7 V5-UNCLEAR surfaces use REST API only (FAILED_TO_VERIFY for absent APIs as honest architectural finding).

## 5. Per-Surface Verification Design

**S1 — Uploaded file removal (`UPLD_DIR/<md5>/`)**

- Populate: DIVA APK upload via POST `/api/v1/upload` → captures hash
- Inspect: `docker exec` + `ls /home/mobsf/.MobSF/uploads/<hash>/`
- Expected-pre: directory exists with APK contents
- Expected-post: directory removed entirely
- Source-code authority: Task 7.5b V5 reading (`shutil.rmtree(UPLD_DIR/<md5>/)`)

**S2 — StaticAnalyzer\* DB tables entry deletion**

- Populate: Scan completion via POST `/api/v1/scan`; creates `StaticAnalyzer<Platform>` row
- Inspect: `docker exec` + `sqlite3 db.sqlite3` → `SELECT * FROM StaticAnalyzerAndroid WHERE MD5 = '<hash>'` (or iOS/Windows per testbed)
- Expected-pre: row exists with scan metadata
- Expected-post: row deleted; query returns empty
- Source-code authority: Task 7.5b V5 reading (4 `StaticAnalyzer*` tables: Android, iOS, Windows, EnqueuedTask)

**S3 — RecentScansDB entry + download-dir filesystem artifacts**

- Populate: Same scan completion as S2; creates RecentScansDB row + download-dir artifacts prefixed `<md5>-`
- Inspect: `docker exec` + `sqlite3 RecentScansDB` query for MD5 + `ls /home/mobsf/.MobSF/downloads/ | grep <md5>-`
- Expected-pre: row + filesystem artifacts present
- Expected-post: row deleted; artifacts removed
- Source-code authority: Task 7.5b V5 reading

**S4 — Suppression registry state** (V5-UNCLEAR)

- Populate: Phase A API discovery output identifies endpoint; probable POST `/api/v1/suppress_by_files` OR `/api/v1/suppress_by_rule` (mobsfscan-derived); synthetic suppression rule injection
- Inspect: GET suppression list endpoint (discovery output)
- Expected-pre: populated suppression rules present
- Expected-post: rules deleted (if cleanup contract complete) OR rules persist (if NOT_RESET)
- Phase A discovery deliverable: exact endpoint paths; FAILED_TO_VERIFY candidate if REST API absent

**S5 — User account state** (V5-UNCLEAR)

- Populate: Phase A discovery; probable POST `/api/v1/user_admin` OR `/api/v1/register`; synthetic user injection
- Inspect: GET user list (discovery output)
- Expected-pre: created user present
- Expected-post: user persists post-cleanup (suspected incomplete) OR user deleted
- Phase A discovery deliverable: likely admin-only OR not REST-exposed (FAILED_TO_VERIFY candidate)

**S6 — Instance settings state** (V5-UNCLEAR)

- Populate: Phase A discovery; probable POST `/api/v1/settings` OR PUT `/api/v1/config`; synthetic settings modification
- Inspect: GET settings endpoint
- Expected-pre: modified setting present
- Expected-post: setting persists post-cleanup OR reset
- Phase A discovery deliverable: exact endpoint paths

**S7 — Per-scan plugin tuning state** (V5-UNCLEAR)

- Populate: Phase A discovery; probable scan-config parameter on POST `/api/v1/scan` OR separate config endpoint
- Inspect: discovery output
- Expected-pre: tuning applied
- Expected-post: tuning persists OR reset
- Phase A discovery deliverable: exact endpoint paths

## 6. Idempotency + Failure Mode Tests

Per Task 7.5c V4 §6 precedent + Task 7.5b V5 source-code edge cases. 4 IF tests beyond per-surface 6-step cycle:

**IF1 — Idempotent delete_scan**: (a) Already-deleted hash (post-prior-cleanup); (b) Never-existed hash (random MD5). Capture response shape for both; verify non-fatal behavior per V2 source-code "Scan not found in Database" framing. ~5min.

**IF2 — Mid-scan delete_scan**: Upload + scan-trigger + immediate `delete_scan` (before scan completes). Capture response (V2 source-code states `"A scan can only be deleted after it is completed"` — verify rejection empirically) + verify post-rejection state intact (scan continues; data preserved). ~10min.

**IF3 — Auth tests**: Document MobSF single-key API auth as canonical finding (no per-permission grading; IF3 N/A per V4 §6 IF3 N/A precedent for ZAP). Variant: `delete_scan` with invalid API key — verify 401/403 behavior. ~5min.

**IF4 — Partial-upload cleanup** (MobSF-specific per V2 source-code orphan-territory edge case): Upload partial file (incomplete; no scan created); call `delete_scan` on partial-upload hash; verify orphan filesystem state via `docker exec` + `ls /home/mobsf/.MobSF/downloads/ | grep <md5>-`. Honest finding: orphan confirmed or denied. ~10min.

## 7. Result Evaluation Framework

**4-verdict categorization (canonical from V4 §7):**

- **RESET_COMPLETE** — surface fully cleaned; post-state matches expected empty
- **PARTIAL_RESET** — surface partially cleaned; some state persists
- **NOT_RESET** — surface unchanged post-cleanup
- **FAILED_TO_VERIFY** — cannot empirically determine (API absent; inspect method unavailable)

**Primary flip-decision verdict (per ADR-008 amendment commit eab7572):**

- **RECOMMEND FLIP** if and only if ALL 4 surfaces (S4 + S5 + S6 + S7) verify RESET_COMPLETE
- **RECOMMEND RETAIN** if ANY S4-S7 surface verifies PARTIAL_RESET / NOT_RESET / FAILED_TO_VERIFY

**Secondary version-drift surveillance verdict (S1-S3 outcomes; informational):**

- S1-S3 verdicts inform empirical confidence in source-code-known scope at MobSF v4.4.6
- Unexpected S1-S3 NOT_RESET surfaces trigger version-drift forward-pin (separate disposition from flip decision)
