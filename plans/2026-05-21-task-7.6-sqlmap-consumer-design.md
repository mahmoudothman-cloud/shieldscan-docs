## 3. Architectural Decisions

### 3.1 Q2 + `1c6041d` Per-Section Adaptor 2nd-Instance Pattern

**Lock:** Per-section adaptor pattern at 2nd instance (MobSF 1st instance + SQLMap 2nd instance). Two adaptor functions in `parser.go`: `adaptInjectionFindings` (per-Parameter blocks; flatten to N per-technique findings) + `adaptDBMSFingerprint` (trailing block; single finding).

**`1c6041d` forward-pin operationally satisfied:** Phase 5.D evaluation now has real 2-instance pattern to consider for DEVELOPMENT-PATTERNS promotion question. 3rd-instance threshold not yet reached; pattern stays at 2 instances pending future consumer.

### 3.2 Q3 Per-Technique Finding Granularity

**Lock:** Per-technique flatten — each technique entry (boolean-blind / error-based / time-based / UNION / stacked-queries) emits discrete finding with Title + Payload + Type. Per-parameter aggregation rejected (loses Payload typed-field; loses per-technique severity differentiation; loses industry-standard granularity).

### 3.3 Q4 DBMS-Fingerprint Emission

**Lock:** Discrete finding per scan when present (DBMS fingerprint only emitted by SQLMap when ≥1 injection found). FindingType=`"dbms_fingerprint"`; Severity=`"info"` (lowercase canonical); Metadata captures `dbms_type` + `dbms_version` + `dbms_os` + `web_app_tech`. No-injection scans emit zero findings.

### 3.4 Q5 ScanConfig.Depth → SQLMap `--level`/`--risk` Mapping

**Lock:** 3-tier alignment with canonical ScanConfig.Depth enum:

| ScanConfig.Depth | --level | --risk | Expected duration |
|---|---|---|---|
| quick | 1 | 1 | ~10–15s (default) |
| standard | 3 | 2 | ~30–60s |
| deep | 5 | 3 | ~3–5min |

### 3.5 Q6 Metadata-vs-Typed Routing

**Typed-field reuse (per ADR-024 + Q6 typed-promotion principle):**

- `Title` (per-technique injection / "DBMS detected: <type> <version>")
- `Severity` (`"high"` or `"critical"` for injection; `"info"` for DBMS)
- `FindingType` (`"sql_injection"` / `"dbms_fingerprint"`)
- `CWEID` (`"CWE-89"` for sql_injection findings)
- `TargetURL` (scan URL)
- `Parameter` (injection parameter name; sql_injection findings)
- `Payload` (injection payload string; sql_injection findings)
- `OWASP` (`"A03:2021 Injection"` for sql_injection findings)

**Metadata keys (snake_case per ADR-027; omit-when-empty):**

- `technique` (per-technique Type; `"boolean-based blind"` / `"error-based"` / etc.)
- `place` (`"GET"` / `"POST"` / `"COOKIE"` / `"HEADER"`)
- `dbms_type` (DBMS finding only)
- `dbms_version` (DBMS finding only)
- `dbms_os` (DBMS finding only)
- `web_app_tech` (DBMS finding only)

**Forward-pin (v1.1+):** `request` + `response` typed-field promotion if log-file parsing adopted; per-payload `http_request_count` Metadata key if useful for downstream analytics.

### 3.6 Q1 Stdout Parsing Architectural Pattern

**Lock:** Consumer `ParseOutput` receives DockerRunner stdout bytes; parses `--disable-coloring` text; log-prefix filter (`[INFO]`/`[WARNING]`/`[ERROR]`/`[CRITICAL]` line prefixes stripped); per-section adaptor dispatch (Q2 lock). No framework Mounts required. Mirrors Trivy/Nmap exec-shape ParseOutput pattern.

### 3.7 Q7 Cookie/Session Auth Forward-Pin

**Lock:** v1 SQLMap supports public unauthenticated targets only. Authentication payload + session cookie management forward-pinned to ADR-015 enablement task. Trigger phrase preserved: ***"Begin ADR-015 enablement task"***.

### 3.8 Q8 PoolMaxSize

**Lock:** PoolMaxSize = 4 (cross-consumer convention per Nmap + Trivy precedents). RunnerTimeout = 30 * time.Minute (matches Trivy precedent; accommodates deep-scan duration ~3–5min).

### 3.9 Q9 Cross-Repo API Routing

**Lock:** Add `"sqlmap"` entry to shieldscan-api `SCAN_TYPE_TOOLS` at both `ScanType.FULL_SPECTRUM` (web+source context; SQLMap canonical for web SQLi) + `ScanType.API` (API-specific scanning; SQLMap canonical for API SQLi alongside existing `nuclei_api` + `zap_api` + `corstest`). Cross-repo coordinated pair commits required (mirrors Task 7.1 D-PLAN-7 pattern).
