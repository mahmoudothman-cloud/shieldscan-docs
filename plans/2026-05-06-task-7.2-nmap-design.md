## 1. Executive Summary

Task 7.2 ships Nmap as the first DockerRunner consumer (per ADR-026 framework). Nmap performs TCP connect scans with service/version detection (`-sT -sV`); output is XML parsed via Go's `encoding/xml` standard library; findings emit one RawFinding per open port at Informational severity with full service/product/version metadata preserved.

The design preserves Task 7.2's "smallest scope, cleanest framework validation" framing while supporting Nmap's dual role: standalone scanner (emitting findings via the existing ADR-017 + ADR-024 + ADR-025 pipeline) and future M8 recon-helper (forward-pinned; Nmap's structured port/service/version data flows into M8's recon pipeline via the same RawFinding metadata payload).

CVE matching, rule-based severity escalation, NSE script enablement, and UDP/SYN/OS detection are explicitly out of scope for v1; each has documented forward-pins to future additive tasks.

Defense-in-depth target validation (Layer 3) lives in BuildArgs to reject loopback, link-local (incl. cloud metadata endpoints), multicast, reserved IANA ranges, and RFC1918-by-default. Layer 1 (shieldscan-api scan-job ownership validation) is documented as required precondition; if Phase 0 implementation-time verification surfaces it as missing or weak, that's a security concern requiring pause-for-direction, not a Task 7.2 scope item.

Network egress policy (Layer 2 / Layer 4) is out of scope; documented as pre-launch infrastructure-hardening task forward-pin.

## 3. Architecture

### 3.1 Final Nmap CLI Invocation Shape
```

nmap -sT -sV -oX - -T4 --host-timeout 25m [-p <port-range>] <target>

```

**Flag rationale:**
- `-sT`: TCP connect scan; no privileges required (per Q2 lock)
- `-sV`: service/version detection; output preserves product + version per Q6 metadata contract
- `-oX -`: XML output to stdout; consumed via `Container.Exec` → `ParseOutput` per Q3 lock
- `-T4`: aggressive timing template; standard for security scans without -T5's reliability concerns
- `--host-timeout 25m`: per-host scan-time bound; 5min buffer below 30min framework timeout
- `-p <port-range>`: omitted when `cfg.Ports == "" || cfg.Ports == "top-1000"` (Nmap default = top 1000); explicit when configured

**Default `--version-intensity 7`** is implicit; per Q8 lock, version-detection NSE invocations are accepted as part of `-sV` semantics.

**Layer 3 target validation** (defense-in-depth per Concerns resolution):

```go
// internal/tools/docker/nmap/validation.go (verify path in Phase 0)

// validateTarget rejects targets that would scan inappropriate networks.
// Layer 1 (shieldscan-api scan-job ownership validation) is required
// precondition; this function is defense-in-depth only.
func validateTarget(target tools.Target, cfg tools.ScanConfig) error {
    ip := net.ParseIP(target.Address)
    if ip != nil {
        // IP literal target; classify
        if ip.IsLoopback() {
            return errors.New("nmap: loopback targets not permitted")
        }
        if ip.IsLinkLocalUnicast() || ip.IsLinkLocalMulticast() {
            return errors.New("nmap: link-local targets not permitted (includes cloud metadata endpoints)")
        }
        if ip.IsMulticast() {
            return errors.New("nmap: multicast targets not permitted")
        }
        if isReservedIANA(ip) {
            return errors.New("nmap: reserved IANA range targets not permitted")
        }
        if isPrivate(ip) && !cfg.AllowPrivateTargets {
            return errors.New("nmap: RFC1918 private targets require explicit AllowPrivateTargets")
        }
        if isShieldScanInfra(ip) {
            return errors.New("nmap: ShieldScan infrastructure targets not permitted")
        }
    }
    // Hostname targets: no IP-level pre-validation; relies on Layer 1 trust
    // + DNS rebinding mitigation forward-pinned to platform team
    return nil
}
```

`validateTarget` is called from `BuildArgs` before constructing the command; failure surfaces as a Run error (caught by ToolRunner contract; scan job marked failed).

`ScanConfig.AllowPrivateTargets` is a new field; verify in Phase 0 whether ScanConfig has a per-tool config surface or shared config model. If shared, the field applies platform-wide (acceptable; tenant-controllable for legitimate internal-network scanning).

`isShieldScanInfra` reads CIDR list from env var (`SHIELDSCAN_INFRA_CIDRS`); empty by default; operator-configured per deployment.

### 3.4 ParseOutput Logic

> **Post-implementation correction (2026-05-06, per shieldscan-engine commit 872b2b0):** §3.4 was drafted pre-implementation assuming `RawFinding.Metadata map[string]string` field existed. Phase 0 verification (V9) surfaced that the field was missing; brainstorming Decision 1 added it via ADR-027 (lands as Phase 5.B alongside this commit). The post-implementation Metadata shape:
>
> - **Required keys (always present):** `host`, `port`, `protocol`, `state`, `service`, `target`
> - **Conditional keys (omitted when empty):** `product`, `version`, `extra_info`, `cpe`, `tunnel`
>
> The `cpe` and `tunnel` keys were added beyond Q6 minimalism per Phase 2 canonical-reference grounding (real Nmap output revealed `<cpe>` child elements + `<service tunnel="ssl">` attribute). Asymmetric-cost meta-principle applied: ~10 LoC + 5 tests now vs M9 task backfill + historical-data gap. Implementation captures both fields; design doc updated post-fact.

```go
// internal/tools/docker/nmap/parser.go (verify path in Phase 0)

// XML schema structs mirror Nmap's nmap-dtd published schema.
type nmapRun struct {
    XMLName xml.Name `xml:"nmaprun"`
    Hosts   []host   `xml:"host"`
}

type host struct {
    Addresses []address `xml:"address"`
    Status    status    `xml:"status"`
    Ports     ports     `xml:"ports"`
}

type address struct {
    Addr     string `xml:"addr,attr"`
    AddrType string `xml:"addrtype,attr"`
}

type ports struct {
    Ports []port `xml:"port"`
}

type port struct {
    Protocol string  `xml:"protocol,attr"`
    PortID   string  `xml:"portid,attr"`
    State    state   `xml:"state"`
    Service  service `xml:"service"`
}

type state struct {
    State  string `xml:"state,attr"`   // "open" | "closed" | "filtered" | etc.
    Reason string `xml:"reason,attr"`
}

type service struct {
    Name      string `xml:"name,attr"`
    Product   string `xml:"product,attr,omitempty"`
    Version   string `xml:"version,attr,omitempty"`
    ExtraInfo string `xml:"extrainfo,attr,omitempty"`
}

// parseOutput converts Nmap XML to RawFindings.
// One RawFinding per open port (per Q6 lock); closed/filtered ports
// not emitted (scan completeness data, not findings).
func parseOutput(stdout []byte) ([]events.RawFinding, error) {
    var run nmapRun
    if err := xml.Unmarshal(stdout, &run); err != nil {
        return nil, fmt.Errorf("nmap: xml parse: %w", err)
    }
    var findings []events.RawFinding
    for _, h := range run.Hosts {
        if h.Status.State != "up" {
            continue  // host down or unknown; no port findings
        }
        hostAddr := primaryAddress(h.Addresses)
        for _, p := range h.Ports.Ports {
            if p.State.State != "open" {
                continue  // closed/filtered/etc.; not emitted
            }
            findings = append(findings, buildFinding(hostAddr, p))
        }
    }
    return findings, nil
}
```

**RawFinding shape per open port:**

```go
RawFinding{
    Title:       fmt.Sprintf("Open port: %s/%s (%s)", p.PortID, p.Protocol, p.Service.Name),
    Severity:    "Informational",
    Description: buildDescription(hostAddr, p),  // "ssh service detected on 192.168.1.10:22. Product: OpenSSH. Version: 8.9p1 Ubuntu 3ubuntu0.4."
    Metadata: map[string]string{
        "host":       hostAddr,
        "port":       p.PortID,
        "protocol":   p.Protocol,
        "state":      p.State.State,
        "service":    p.Service.Name,
        "product":    p.Service.Product,
        "version":    p.Service.Version,
        "extra_info": p.Service.ExtraInfo,
        "target":     <original-target-from-Run-context>,  // for audit-log + abuse-detection
    },
    // Fingerprint, ToolName, EngineCategory, DiscoveredAt populated by
    // DockerRunner enrichment loop per ToolRunner contract (runner.go:65-69)
}
```

## 5. Data Flow
```

Worker receives scan job (target + ScanConfig with optional cfg.Ports) ↓ Layer 1 trust assumption: shieldscan-api validated tenant target ownership at scan-job creation ↓ DockerRunner.Run(ctx, target, cfg) ↓ [Layer 3 validation] buildArgs → validateTarget(target, cfg) → if reject, return "nmap: target not permitted: <reason>" ↓ Pool.Checkout(ctx) → warmed instrumentisto/nmap container (lazy spin-up if pool empty; reuse warmed container if available) ↓ container.Exec(ctx, args) → XML stdout (per ADR-026 cleanup-uses-parent-context anti-pattern: defer Pool.Return uses context.WithoutCancel(ctx) + 30s timeout for cleanup safety) ↓ parseOutput(stdout) → []RawFinding (one per open port; Informational severity) ↓ DockerRunner enrichment loop populates ToolName="nmap", EngineCategory=<verified>, DiscoveredAt=<timestamp>, Fingerprint=<host+port+protocol+service hash> ↓ findings returned to caller (worker.Processor) ↓ [ADR-013 sole-writer atomicity preserved; runner does not persist] worker.Processor → emits job_completed event with findings inline (per ADR-017) ↓ shieldscan-api findings-ingest consumer (per ADR-025) → persists RawFindings to database ↓ [Forward-pin: M8 Recon-First Pipeline] Future M8: same parsed structured data feeds recon pipeline; downstream scanners (Nuclei, ZAP, SQLMap) consume host+port+service+version metadata from RawFinding.Metadata to populate their own target lists

```

## 6. Error Handling

| Failure Mode | Detection | Response |
|---|---|---|
| Target validation rejects (Layer 3) | `validateTarget` returns error | DockerRunner.Run returns `"nmap: target not permitted: <reason>"`; scan job marked failed |
| Image pull fails | Pool.Checkout error | DockerRunner.Run returns `"nmap: pool checkout: <err>"` |
| Container exec fails (network, container died, ctx cancel) | Container.Exec error | DockerRunner.Run returns `"nmap: exec: <err>"`; Pool.Return preserves pool integrity |
| Non-zero exit code | Container.Exec returns exit code | `ExitCodeLenient: false` → DockerRunner.Run returns `"nmap: non-zero exit code N"` |
| XML parse error | xml.Unmarshal error | DockerRunner.Run returns `"nmap: xml parse: <err>"` |
| Primary context timeout | ctx cancellation propagates | Container.Exec returns ctx.Err(); cleanup uses context.WithoutCancel; pool integrity preserved |
| No findings (target has no open ports) | parseOutput returns `[]RawFinding{}` | Valid result; not an error; downstream consumes empty findings normally |
| Per-host failures within multi-host target | Nmap continues; partial XML | parseOutput emits findings for completed hosts; failed-host data documented in Nmap XML's host status |

## 7. Testing Strategy

**Test pyramid** mirroring f5d77c8 patterns:

1. **Unit tests** (in-package):
   - Constructor (`NewRunner`) field validation
   - BuildArgs port-range translation matrix (top-1000 default → no `-p`; explicit values → `-p X`; edge cases like `""` and invalid syntax)
   - Layer 3 target validation: each rejection path (loopback, link-local, multicast, RFC1918, ShieldScan infra, reserved IANA) covered explicitly
   - Parser: all 7 testdata XML fixtures producing expected RawFinding shapes
   - Forward-compatibility: unknown XML fields gracefully ignored (encoding/xml default behavior; pinned by `unknown-fields.xml` fixture)

2. **DockerRunner integration test** (light; stub-backed):
   - DockerRunner.Run with stubDockerClient returning canned XML
   - Verify finding count + metadata preservation + enrichment fields populated
   - Verify pool checkout/return lifecycle around scan execution

3. **Race detector** (full repo):
   - All tests run under `go test -race -count=1` per project standard
   - WarmPool concurrency is already covered by f5d77c8's tests; Nmap consumer adds no new concurrency surface

4. **Out of v1 scope:**
   - Real-Docker integration test against running Nmap container (deferred to dedicated test infrastructure tasks)
   - End-to-end test against live target (requires test target infrastructure)
   - Performance/load tests (deferred to dedicated benchmarking tasks)

**Forcing-function tests** (regression guards):
- Test pinning Layer 3 target validation: future engineer who removes guardrails fails the test
- Test pinning XML schema struct field assignments: future engineer who refactors parser breaks the test
- Test pinning RawFinding.Metadata structure: future engineer who reshapes metadata breaks downstream consumption

**Post-implementation acknowledgment (2026-05-06, per shieldscan-engine commit 872b2b0).** The brainstorming → design → implementation chain for Task 7.2 surfaced 10 factual deviations across Phases 1-3 (3 Phase 1 + 1 Phase 2 + 6 Phase 3; documented in shieldscan-engine `DRIFT-LOG.md` entry 4 of the 872b2b0 commit). Two of these were genuinely load-bearing bugs in pre-implementation guidance:

1. **`stripPort` IPv6 bug.** Phase 1 verbatim's "no further colons in suffix" check incorrectly stripped bare `::1` to `:`. Per RFC4291 IPv6 has multiple colons; the correct invariant is `strings.Count(addr, ":") == 1` (single-colon form rules out any IPv6 representation). Caught at design-spec-reading time.

2. **Multicast/link-local ordering bug.** Phase 1 verbatim ordered `IsLinkLocalUnicast()` before `IsMulticast()`. Address `224.0.0.1` is link-local-multicast per RFC5771 (within 224.0.0.0/4 broader multicast space) — Go's `IsLinkLocalMulticast()` returns true; first-checked branch fired with wrong "link-local" rejection message. Reordered: `IsMulticast()` first (catches 224.0.0.0/4 in full), then `IsLinkLocalUnicast()` only (cloud metadata at 169.254.169.254).

Three architectural decisions surfaced at validation gates rather than during implementation:

1. **CPE + Tunnel inclusion in v1 Metadata.** Phase 2 canonical-reference grounding (real Nmap 7.94 XML output via `instrumentisto/nmap:7.94` against `scanme.nmap.org`) revealed `<cpe>` child elements + `<service tunnel="ssl">` attribute. Held to Q6 minimalism initially; surfaced for direction; resolved as additive (~10 LoC + 5 tests) rather than future-task backfill.

2. **Framework signature adapter pattern.** Phase 3 implementation surfaced that `DockerRunner.BuildArgs` has no error return + `DockerRunner.ParseOutput` has no target parameter. Two adapters (`buildArgsAdapter` swallowing validation errors → empty args → exec-time failure; `parseOutputForDocker` calling `parseOutput` with empty target) bridged the gap within consumer package; framework changes deferred until 2nd consumer needs same adapters.

3. **Pool shutdown placement.** `Startup` struct is setup-only; no `Shutdown` method exists. Inverted from verbatim's "add to Startup.Shutdown" suggestion: pool shutdown wired in `run.go` drain path with `context.Background()` + 30s grace — this is the 3rd instance of the cleanup-uses-parent-context anti-pattern (M6.7 Wapiti + ADR-026 DockerRunner.Run + Task 7.2 runMain). DEVELOPMENT-PATTERNS promotion threshold met; lands in Phase 5.C alongside this design doc fixup.

The discipline pattern (verify-then-adapt-then-document; surface architectural deviations at gates; commit message footnotes enumerate factual deviations) held throughout. Pre-implementation guidance is unreliable specifically because edge-case interleavings + framework-signature mismatches + canonical-output realities surface during implementation; the discipline pattern catches these transparently before commit.
