## 1. Executive Summary

Task 7.4 ships MobSF as the second DockerServiceRunner consumer (per Task 7.5b framework; commit 1306ca8). MobSF is a MAST (Mobile Application Security Testing) tool — runs static analysis against uploaded mobile binaries (`.apk` / `.xapk` / `.aab` / `.ipa`). Marks shieldscan's first mobile-binary scanning capability + first R2 cloud storage integration in engine.

**Q5 Architectural Decision (Locked First Per Path 1):** Per Task 7.5c V4 verification execution (commit bfccef8) directly applicable to MobSF, Q5 locks `cfg.EphemeralContainer = true` v1 default (mirroring Task 7.5b V4 Option γ for ZAP). Task 7.5c's S7/S8/S9 findings empirically demonstrated ZAP `newSession` is session-state-only; user/policy/plugin state is configuration-scoped (instance-level). MobSF's V5 forward-pin from Task 7.5b explicitly flagged "Suppression/user/settings table UNCLEAR" — same architectural failure mode possible. Asymmetric-cost reasoning per §14.1: bounded ephemeral startup cost vs unbounded multi-tenant configuration-state-leakage risk where cleanup contract is UNCLEAR. ADR-008 receives addendum at Phase 5.B acknowledging architectural commitment refinement. Warm-pool path forward-pinned to Task 7.5d empirical verification.

Single scan mode shipped v1: static analysis only (matches pricing §9.1 single-tier Mobile scans + MobSF API surface tightly-bounded reality — no per-scan tunables exposed via REST). Multi-mode framework consumes existing wire schema scaffolding (`events.JobMobileConfig.AnalysisType` field pre-existed per Phase 0 V1 finding); dynamic analysis (requires Android emulator infrastructure) + source code analysis forward-pinned to v2 scope.

Both Android + iOS platforms shipped v1 (Q2(iv) lock; honors shieldscan-api MobilePlatform enum pre-existing per V6); consumer-side file-extension validation against Platform field surfaces wire/file mismatch failure mode explicitly.

R2 binary integration via consumer-local R2 client (Q6.1 lock; 1-instance threshold; framework promotion at 2nd-instance trigger per Phase 5.D pattern); full download to worker disk before MobSF upload (Q6.2 lock); engine env vars for R2 credentials v1 (Q6.4 lock; pre-signed URL pattern forward-pinned to ADR-015 enablement task); preserves Phase 2 OUTCOME b discipline (ZERO shieldscan-api files modified).

RawFinding mapping shape: `report_json` bulk fetch + single-pass per-section parser (Q8(iii) lock); 8 v1 contributing sections (`code_analysis` primary + `manifest_analysis` + `permissions` + `network_security` + `binary_analysis` + `certificate_analysis` + `secrets` + `trackers`); typed-fields-first + Metadata-for-remainder per Nmap + ZAP precedent. **C5 typed-fields-first pattern reaches 3-instance threshold** at Task 7.4; Phase 5.D promotion to DEVELOPMENT-PATTERNS.md entry #6 candidate.

Authentication via framework helper directly: `WithAPIKeyHeader("X-Mobsf-Api-Key", apiKey)` (Q7(A) lock; doc-backed canonical per Q4 verification bonus finding H source-code reading of `api_middleware.py`); validates Task 7.5b framework design as legitimate consumer (2nd-instance of `WithAPIKeyHeader` helper after framework example).

### 3.2 Type Definitions

Consumer-side types (in `mobsf` subpackage):

```go
type Config struct {
    APIKey        string
    MaxAPKSizeMB  int               // default 500MB; rejects oversized binaries pre-fetch
    R2Config      R2Config          // env-var-loaded at runtime
    MobSFTimeout  time.Duration     // default 30min; per-scan ceiling
}

type R2Config struct {
    AccountID       string
    AccessKeyID     string
    SecretAccessKey string
    Bucket          string
}

func NewBuildScan(cfg Config) func(ctx context.Context, target tools.Target, scanCfg tools.ScanConfig, client *service.Client) ([]events.RawFinding, error)
```

Consumer constructs runner:

```go
runner := &service.DockerServiceRunner{
    ToolName:     "mobsf",
    ToolCategory: "mast",
    ServiceConfig: service.ServiceConfig{
        Image:              mobsfImageDigest,
        ContainerPort:      8000,
        EphemeralContainer: true,
        ReadinessEndpoint:  "/api/v1/ping",
        ReadinessTimeout:   120 * time.Second,
        AuthFunc:           service.WithAPIKeyHeader("X-Mobsf-Api-Key", apiKey),
        CleanupFunc:        nil,
    },
    BuildScan: mobsf.NewBuildScan(cfg),
    Log:       log,
}
```

**Wire schema pre-existing types** (per Phase 0 V1; consumer reads):
- `events.JobMobileConfig` with `UploadRef string` (R2 URL `"r2://bucket/key"`); `Platform string` (`"android" | "ios"`); `AnalysisType string` (`"static"` v1; `"dynamic"`/`"source"` forward-pinned)
- `Target.MobileUploadRef` + `Target.MobileConfig` pre-existing fields in `internal/tools/runner.go`

**RawFinding mobile-evidence typed fields** (per Phase 0 V1; consumer populates):
- `MobileOS`, `Permission`, `ComponentName`, `CodeFile`, `CodeLine`, `CodeSnippet`, `CVSSScore`

### 3.3 Lifecycle Flow

```
Worker scan-job
    ↓
DockerServiceRunner.Run(ctx, target, scanCfg)
    ↓
EphemeralContainer = true path:
    ServiceContainerFactory creates fresh MobSF container
    spinUp readiness probe → /api/v1/ping
    BaseURL = http://127.0.0.1:<dynamic-port>
    defer container.Stop
    ↓
Construct Client with WithAPIKeyHeader("X-Mobsf-Api-Key", apiKey)
    ↓
BuildScan(ctx, target, scanCfg, client) executes consumer scan logic per Q1–Q9 locks:
    (a) target validation (TargetType=mobile; MobileUploadRef non-empty;
        Platform∈{android,ios}; AnalysisType=static v1)
    (b) R2 fetch — consumer-local R2 client downloads binary to worker-local
        /tmp staging
    (c) file-extension validation against Platform per Q2(iv)
    (d) MobSF upload — POST /api/v1/upload multipart with binary; capture
        hash from response
    (e) MobSF scan — POST /api/v1/scan with hash parameter; synchronous
        (Q4 v1 sync mode); awaits scan completion
    (f) report fetch — POST /api/v1/report_json with hash; receive bulk JSON
    (g) parse report_json → RawFindings per Q8(iii) per-section walker
    (h) return findings
    (i) defer cleanup: worker-local /tmp staging file removed;
        container.Stop on scan-end
    ↓
Findings flow to framework enrichment + ADR-017 inline pipeline → ADR-025 ingest
```

### 3.4 RawFinding Mapping (Q8 verification-grounded)

Per Q8 surface report mapping table: source = `report_json.code_analysis.findings[rule_id]`; per-rule object iterated; per-file entry (`files[]` array) produces N RawFindings (one per file-match).

**Typed fields:**
- `Title` ← `rule_id` (or `metadata.description`-first-sentence; Phase 0 forward-pin V8 decision)
- `Severity` ← `mapMobSFSeverity(metadata.severity)` — `ERROR→"high"`; `WARNING→"medium"`; `INFO→"info"`; `secure→drop`; `hotspot→"low"`; unknown→`drop=true` defensively
- `Description` ← `metadata.description`
- `CWEID` ← `extractCWENumber(metadata.cwe)` — extracts numeric portion `"89"` from `"CWE-89: SQL Injection"`; description suffix preserved in `Metadata.cwe_description`
- `CVSSScore` ← `metadata.cvss` (typed float)
- `References` ← `[metadata.reference]`
- `Tags` ← `extractMobSFTags(metadata.owasp-mobile, metadata.masvs)` — flattened `"OWASP-M7"` + `"MASVS-code-8"` forms
- `CodeFile` ← `files[].file_path`
- `CodeLine` ← `files[].match_lines[0]`
- `CodeSnippet` ← `files[].match_string`
- `MobileOS` ← `target.MobileConfig.Platform`
- `Permission` / `ComponentName` populated from `manifest_analysis` + `permissions` sections (per-section adaptor)

**Metadata snake_case keys:** `mobsf_section` (rule's source section); `app_name`; `package_name`; `mobsf_file_hash` (md5); `pattern_type` (omit empty); `match_position` (omit empty); `platform` (android/ios for cross-tool correlation); `target` (consumer-side: `ScanConfig.Target.MobileUploadRef` OR app `package_name` — cross-tool correlation key per ADR-027 §M9 forward-pin); `cwe_description` (omit empty); raw section JSON in `tags_raw_json` if needed for audit.

Identity fields (`ScanID`, `ToolName`, `EngineCategory`, `DiscoveredAt`, `Fingerprint`) populated by `DockerServiceRunner.Run` enrichment loop per Task 7.5b service.go pattern + Task 7.3 precedent.

**Post-Implementation Drift Annotation (Phase 5.A; 2026-05-10):** Phase 0 empirical verification at pinned MobSF digest `sha256:72311e3553ca2c21043923cace27ed99f800cd641e9368160406779516dd774e` (v4.4.6) surfaced 6+ drifts vs source-code-reading-based pre-implementation mapping table above. All drifts auto-corrected in Phase 1 (shieldscan-engine commit c15a60d):

- **D1 — files shape correction:** Pre-implementation mapping anticipated `files: [{file_path, match_lines[], match_string, match_position}]` list-of-structured-objects. Empirical reality: `files: {file_path: "csv_line_string"}` dict-of-path-to-CSV-line-numbers. No `match_string`; no `match_position`. Phase 1 parser parses via `strings.Split(linesCSV, ",")` + `strconv.Atoi`; iterates `for filePath, linesCSV := range files`.
- **D2 — metadata.ref key (3-letter):** Pre-implementation mapping anticipated `metadata.reference`. Empirical reality: `metadata.ref` (3-letter); often null for code_analysis rules. Phase 1 `codeAnalysisMetadata.Ref` json tag aligns.
- **D3 — owasp-mobile colon format:** Pre-implementation mapping anticipated `"M7 - Poor Code Quality"` (hyphen). Empirical reality: `"M7: Client Code Quality"` (colon-separated). Phase 1 `extractMobSFTags` splits at `:` → `"OWASP-M7"` form.
- **D4 — masvs full canonical form:** Pre-implementation mapping anticipated `"code-8"` short form. Empirical reality: `"MSTG-STORAGE-2"` full canonical form. Phase 1 pass-through directly → `"MASVS-STORAGE-2"` tag; skip empty.
- **V5 — severity lowercase:** Pre-implementation mapping anticipated `INFO/WARNING/ERROR` uppercase. Empirical reality: lowercase `"high"`, `"warning"`, `"info"`. Phase 1 `mapMobSFSeverity` `strings.ToLower` + maps: `"high"→"high"`, `"warning"→"medium"`, `"info"→"info"`, `""/"secure"/unknown→drop=true` (defensive).
- **V17 — certificate_findings list-of-3-element-lists:** Pre-implementation mapping anticipated dict-of-objects shape. Empirical reality: `certificate_findings: [[severity, title, description]]` — list-of-3-element-lists (positional). Phase 1 `adaptCertificateFindings` decodes `[][]string` + positional triple. Highly idiosyncratic among MobSF sections.
- **V8 — rule_id as Title (decision-lock):** Pre-implementation mapping was forward-pinned between (a) `Title ← rule_id` directly OR (b) `Title ← metadata.description`-first-sentence. Phase 0 empirical sample (DIVA APK) showed rule_ids are human-readable snake_case (e.g., `android_sql_raw_query`, `android_logging`, `android_read_write_external`). Decision-lock: Phase 1 parser sets `Title = rule_id` directly.

Per-section heterogeneity confirmed empirically (V11–V17): `manifest_analysis` = list-of-objects with rule/title/severity/description/name/component[]; `permissions` = dict-keyed (filter `status=="dangerous"`); `binary_analysis` = list × 8 sub-checks per binary (`nx`, `pie`, `stack_canary`, `relocation_readonly`, `rpath`, `runpath`, `fortify`, `symbol`); `secrets` = list-of-strings (NOT objects); `certificate_findings` = list-of-3-element-lists (per V17 above); `trackers` + `network_security` forward-pinned (V13/V16 empty in DIVA testbed; populated-state shape unknown). Phase 1 `sections.go` implements per-section adaptor pattern.

V18 `delete_scan` response shape (audit-only; Task 7.5d preparation): `{"deleted": "yes"}` idempotent on existing hash. Phase 1 `deleteScan` POST/x-www-form-urlencoded; best-effort warn-on-fail.

Cumulative §3.4 mapping table CORRECTED state lives in shieldscan-engine commit c15a60d at `internal/tools/docker/service/mobsf/parser.go` + `sections.go`.
