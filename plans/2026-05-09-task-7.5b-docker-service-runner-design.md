## 1. Executive Summary

Task 7.5b ships **DockerServiceRunner** — the M7 framework for HTTP-API-shaped Docker tools. Distinct from DockerRunner (Task 7.5a, exec-shaped tools like Nmap) by handling long-running service containers that expose REST APIs rather than one-shot CLI invocations. Two consumer tasks depend on this framework: Task 7.3 (ZAP) and Task 7.4 (MobSF).

The framework provides **mid-scope abstraction** per Q1 lock: container lifecycle + HTTP service readiness probing + custom shieldscan HTTP client built on `net/http` stdlib + polling primitive with exponential backoff. Consumer-specific concerns (scan-job creation/poll/fetch shape; result parsing; auth token sourcing) remain consumer-side.

> **Phase 0 resolution locks (2026-05-09).** The original brainstorming chain (Q1-Q9 below) misframed Task 7.5b as "design from scratch." Phase 0 verification surfaced four corrections that revise the framing without invalidating the brainstorming locks themselves:
>
> 1. **V8 Replace** — Task 7.5b *replaces* an existing `internal/tools/docker_service.go` (M5.3 + ADR-006; 366 LoC; **zero active consumers** per Phase 0.5 verification). New framework lands at `internal/tools/docker/service/` subpackage per V8 Option (c); old file deleted as part of Phase 4 atomic commit.
> 2. **V2 Extend Task 7.5a** — DockerServiceRunner needs custom container creation (port mapping; no `sleep infinity` Cmd override). WarmPool's existing `spinUp` is hardcoded; Task 7.5b extends Task 7.5a's framework with a `ContainerFactory` hook (~30-50 LoC additive) rather than building a parallel pool primitive (~150 LoC). Backward-compat for DockerRunner (Nmap) consumer preserved via `DefaultContainerFactory`.
> 3. **V4 ZAP ephemeral default** — ZAP `newSession` reset surfaces (spider history, ascan history, alert list, target context, scope config, authenticated session, user contexts, attack policies, add-on plugin state) **NOT VERIFIED** in public REST API docs. Per asymmetric-cost meta-principle: bounded ephemeral-startup cost (~3.6 GB ZAP image — slow first-pull but per-scan spin-up is bounded) is preferable to unbounded cleanup-vulnerability cost. `cfg.EphemeralContainer = true` is ZAP v1 default; warm-pool startup amortization deferred to dedicated future verification task.
> 4. **V5 MobSF md5-tracked cleanup** — Phase 0 source-code reading of MobSF's `delete_scan` confirmed per-scan-by-hash deletion model (not blanket reset). Consumer tracks `lastScanMD5` via `CleanupFunc` closure capture; WarmPool failure-replace semantics handle in-progress-scan + network-failure edge cases. Suppression/user/settings table persistence remains UNCLEAR but not relevant for v1 single-tenant deployments.

Container lifecycle uses warm pool with strict reset cleanup per Q5 lock — `cfg.EphemeralContainer` flag provides opt-out for high-security scenarios where shared infrastructure isn't acceptable. **Cleanup-leaves-ready-state assumption** (Q6 lock) means readiness probe runs only at pool spin-up; cleanup hooks must restore service to ready state via tool-specific reset API call (ZAP `newSession`; MobSF `delete_scan`). Cleanup correctness is **security-relevant** — incorrect cleanup risks cross-tenant data leakage.

Network configuration uses bridge networking with **dynamic port mapping bound to 127.0.0.1** per Q7 lock — multi-container-safe by construction; localhost-only binding is defense-in-depth complementing future Layer 4 hardening tasks.

Authentication delegates to consumer via `AuthFunc` field with framework-provided typed helpers (`WithAPIKeyHeader`, `WithBearerToken`) per Q8 lock.

`BuildScan` is consumer-defined; receives target + scan config + framework HTTP client; returns RawFindings or error. The framework provides `Client` + container lifecycle; consumer drives the scan logic (create job → `PollUntil` status → fetch results → parse to RawFindings).

#### Post-implementation deviation notes (per shieldscan-engine commit 1306ca8)

Cross-package interface visibility surfaced 3 deviations during Phase 1; each was auto-corrected and documented in DRIFT-LOG.md (Task 7.5b entry; engine commit 1306ca8):

- **D1.** `DockerClient = dockerClient` type alias added to `internal/tools/docker/container.go` to enable cross-package factory function literals. The `dockerClient` interface is unexported by design; the alias preserves all internal references while permitting the new `internal/tools/docker/service/` subpackage to declare typed function literals matching `ContainerFactoryFunc`.
- **D2.** `ContainerInspect` method added to the `dockerClient` interface for `ServiceContainerFactory` dynamic-port discovery. `productionClient` gained a passthrough; 3 stub test files were updated (`docker/testhelpers_test.go`, `docker/nmap/testhelpers_test.go`, `docker/container_test.go` `fakeClient`) to satisfy the extended interface.
- **D3.** `NewServiceContainer(id, image, baseURL, cli, log) *Container` exported constructor added to `internal/tools/docker/container.go`; `BaseURL` exported field added to the `Container` struct. The struct's `cli`/`log` fields remain unexported; the constructor is the only cross-package construction path. Existing `Container` internal usage preserved unchanged.
- **D4.** `PollOpts.MaxDuration` default in this design doc originally referenced `ServiceConfig.ScanTimeout`. That field did not exist on `ServiceConfig` (and adding it would have introduced speculative coupling). Phase 1 implementation adopted a flat 30-minute framework-level default via `normalizePollOpts` in `internal/tools/docker/service/client.go`. Consumers may override per-call by passing a non-zero `PollOpts.MaxDuration` to `Client.PollUntil`.

### 3.3 Lifecycle Flow

```
Worker receives scan job
    ↓
DockerServiceRunner.Run(ctx, target, cfg)
    ↓
┌─ IF cfg.EphemeralContainer (e.g., ZAP v1 per V4 lock) ─┐
│   Skip Pool entirely; create fresh container directly: │
│     ServiceContainerFactory(opts).spinUp(ctx, ...)     │
│     ContainerCreate with PortBindings (127.0.0.1:dyn)  │
│     ContainerStart                                     │
│     ContainerInspect → discover dynamic host port      │
│     BaseURL = "http://127.0.0.1:<dynamic-port>"        │
│     waitForReady(ctx, BaseURL+ReadinessEndpoint, ...)  │
└────────────────────────────────────────────────────────┘
    ↓
┌─ ELSE (warm pool path; e.g., MobSF per V5 lock) ───────┐
│   Pool.Checkout(ctx)                                   │
│     cache miss → spinUp uses ServiceContainerFactory   │
│       (same steps as ephemeral branch above)           │
│     cache hit → reuse warmed container; BaseURL known  │
└────────────────────────────────────────────────────────┘
    ↓
Construct Client{BaseURL, HTTPClient, AuthFunc, Log}
    ↓
Consumer's BuildScan(target, cfg, client)
    [typically: client.Post to create scan → client.PollUntil for status →
     client.Get for results → parse to RawFindings]
    ↓
┌─ IF cfg.EphemeralContainer ────────────────────────────┐
│   Container.Stop + ContainerRemove via defer           │
│   (no Pool.Return; container destroyed end-of-scan)    │
└────────────────────────────────────────────────────────┘
    ↓
┌─ ELSE (warm pool path) ────────────────────────────────┐
│   Pool.Return(ctx, container) via defer                │
│     CleanupFunc with context.WithoutCancel(ctx) + 30s  │
│       timeout per DEVELOPMENT-PATTERNS entry #5        │
│     on success: container returned to pool             │
│     on failure: container stopped + replaced (handles  │
│       MobSF in-progress-scan + network-failure cases)  │
└────────────────────────────────────────────────────────┘
    ↓
Findings flow to ADR-017 inline pipeline → ADR-025 ingest consumer
```

### 3.4 Cleanup Hook Contract

CleanupFunc is security-relevant. Failure leaves cross-tenant data leakage risk.

**ZAP CleanupFunc semantics (V4 Option γ resolution).** `cfg.EphemeralContainer = true` is ZAP's v1 default. CleanupFunc is unused for ZAP because each scan creates a fresh container; the container is destroyed at scan end via `Container.Stop + ContainerRemove`. Rationale: ZAP `newSession` cleanup contract has 9 reset surfaces NOT VERIFIED in public docs (per Phase 0 V4); security-consequential uncertainty side-stepped via fresh-container-per-scan. **Forward-pinned:** dedicated V4 verification task (see §5) may flip the default if `newSession` is verified COMPLETE.

**Post-Execution Note (Task 7.5c Phase D.2, 2026-05-09):** V4 ZAP cleanup contract verified empirically per Task 7.5c execution (shieldscan-docs commit 124f5aa). Cumulative verdict: **RECOMMEND RETAIN `cfg.EphemeralContainer = true`**. Three surfaces fail clean reset under `newSession`: S7 PARTIAL_RESET (orphan user records persist); S8 NOT_RESET (custom scan policies survive); S9 NOT_RESET (per-policy attack-strength tuning persists). Architectural insight: ZAP's `newSession` is session-state-only; user/policy/plugin-strength state is configuration-scoped (instance-level). Warm-pool path with `newSession` cleanup ruled out by these findings. V4 Option γ ephemeral default empirically correct as safety-conservative lock — NOT a transitional state pending future flip.

**MobSF CleanupFunc semantics (V5 Option γ resolution).** `cfg.EphemeralContainer = false` (warm pool); CleanupFunc closure captures consumer-side `lastScanMD5` state across scans; cleanup calls `/api/v1/delete_scan` with that hash. Per Phase 0 V5 source-code verification, `delete_scan` removes:

- Uploaded APK/IPA file (`shutil.rmtree(UPLD_DIR/<md5>/)`)
- 4 StaticAnalyzer\* DB tables (Android, iOS, Windows, plus EnqueuedTask)
- RecentScansDB entry
- Filesystem artifacts under download-dir prefixed `<md5>-`

Cannot delete in-progress scans — returns `"A scan can only be deleted after it is completed"`; WarmPool failure-replace semantics handle this case (cleanup error → container stopped + replaced; pool slot opens for spinUp). Partial-upload edge case (upload started, scan never created) returns `"Scan not found in Database"` non-fatally; orphan filesystem artifacts may remain (acceptable in v1; per-scan ephemeral filesystem isolation handles future tightening). Suppression / user / settings tables persistence UNCLEAR per Phase 0; not currently relevant for v1 single-tenant ZAP/MobSF deployments; revisit if multi-tenant MobSF lands.

```go
// MobSF cleanup pattern (V5 Option γ):
type mobsfState struct {
    lastScanMD5 string
}

func mobsfCleanup(state *mobsfState, cfg ServiceConfig) docker.CleanupFunc {
    return func(ctx context.Context, container *docker.Container) error {
        cleanupCtx, cancel := context.WithTimeout(context.WithoutCancel(ctx), 30*time.Second)
        defer cancel()
        if state.lastScanMD5 == "" {
            return nil // no prior scan to clean
        }
        // call /api/v1/delete_scan with state.lastScanMD5 via HTTP client
        return mobsfDeleteScan(cleanupCtx, container.BaseURL(), state.lastScanMD5)
    }
}
```

DEVELOPMENT-PATTERNS entry #5 (cleanup-uses-detached-context) applies — `context.WithoutCancel(ctx) + 30s` for in-scope cleanup.
