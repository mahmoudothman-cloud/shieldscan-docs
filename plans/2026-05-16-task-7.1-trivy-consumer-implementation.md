## 3. Architectural Decisions (Plan-Level Locks)

Phase 0 v2 verification surfaced 3 architectural-decision territories beyond design-doc Q1–Q9 brainstorming chain. All locked at plan landing for Phase 1 implementation.

### 3.1 X1 — pkg_path Sourcing (DRIFT-B1 disposition)

**Lock:** Parse `pkg_path` from `Vulnerability.PkgIdentifier.PURL` field.
**Implementation:** Helper function `extractPkgPathFromPURL(purl string) string` in `parser.go`; parses purl scheme `pkg:type/namespace/name@version[?qualifiers][#subpath]` per PURL spec; returns subpath or empty string.
**Omit-when-empty discipline:** If PURL absent OR parsing fails, `pkg_path` Metadata key omitted per ADR-027 convention.
**Rationale:** PURL is industry-standard package URL; parsing logic well-defined; gives semantic path information. Cross-reference lookup via parent `Result.Packages[]` (Option ii) requires PkgID cross-reference complexity. Drop (Option iii) loses contract commitment per Q6 lock.

### 3.2 X2 — CVSS-Vendor-Priority Logic (DRIFT-B2 HIGH disposition)

**Lock:** Helper function `extractCVSSScore(cvss map[string]TrivyCVSS) float64` with vendor priority chain.
**Priority chain:** `nvd.V3Score → redhat.V3Score → ghsa.V3Score → nvd.V2Score → 0`.
**Implementation:** Iterate vendor priority list in fixed order; return first non-zero V3Score; fall through to NVD V2Score; return 0 if all absent.
**Rationale:** NVD canonical authority for vulnerability data; Red Hat industry-standard for OS-package CVEs (often NVD-absent); GHSA authoritative for code-package GitHub-tracked vulnerabilities; V2 fallback for legacy CVE entries without V3 scoring. Empirical Phase 0 v2 confirmed multi-vendor CVSS map shape; NVD-only narrow (Option a) misses Red Hat OS-package authoritative scoring.
**Pattern intentionality:** Convention naming mirrors `mapTrivySeverity` (helper function shape); not a severity-normalization-helper instance (different domain); may surface as new helper-shape candidate at Phase 5.D evaluation rigor.

### 3.3 X3 — Metadata-Key Contract Extension (DRIFT-B3 disposition)

**Lock:** Conservative extension — v1 contract adds `purl` + `primary_url` only.

**v1 Metadata key contract (Trivy parser):**

- **Existing typed-field reuse (no Metadata):** `ComponentName` (from `PkgName`); `CVSSScore` (from `extractCVSSScore` helper)
- **ADR-027 canonical Metadata keys:** `component_name`, `component_version`, `package_manager`, `license`, `installed_path`
- **SCA-specific Metadata keys:** `pkg_path` (from X1 PURL parse), `installed_version`, `fixed_version`, `vulnerability_id` (CVE), `target` (correlation key per C5), `references`, `class`, `type`
- **Container-specific Metadata keys (image mode only):** `layer_digest`, `os_family`, `os_version`
- **NEW Phase 0 v2 extension (per X3):** `purl`, `primary_url`

**Forward-pin (v1.1+ extension candidates):** `data_source`, `severity_source`, `published_date`, `last_modified_date`.

**Rationale:** `purl` is canonical package URL form (high-value for M9 cross-tool correlation per design doc §4); `primary_url` is canonical vulnerability reference URL (high-value for UX). 4 deferred candidates preserve v1 bounded scope; M9 correlation work surfaces specific Metadata-key requirements at that task scope.

### 3.4 Nmap Forward-Pin (BuildArgs error-return) — Option α Disposition

**Lock:** Acknowledge pre-existing Nmap forward-pin (Nmap source lines 89–95 explicitly call out Trivy as affected consumer for BuildArgs error-return framework extension). Defer framework extension to v1.1+.
**Implementation:** Trivy BuildArgs functions (`buildArgsImage`, `buildArgsFs`) follow current signature `func(target string, cfg ScanConfig) []string`. Validation errors propagate via empty `[]string` return + warning log; `Run()` detects empty args → error path.
**Rationale:** ADR-026 line 2093 anticipated framework-gap path provides escape hatch if empirical Phase 1 implementation surfaces BuildArgs error-return as actual gap; additive framework change at v1.1+ task if needed. Preserves Task 7.1 v1 bounded scope per Q1 lock.
